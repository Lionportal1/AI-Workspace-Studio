# Research Source Verification

1. Define what is unknown, what is time-sensitive, and which claims could change the implementation.
2. Prefer authoritative release notes, source repositories, standards and official documentation over search snippets.
3. Compare conflicting sources by version, date, platform and actual behavior; distinguish verified facts from inference.
4. Produce a short evidence ledger with source URLs, access dates, confidence and unresolved gaps.
5. Validate any proposed command or API against the project runtime before recommending deployment.
