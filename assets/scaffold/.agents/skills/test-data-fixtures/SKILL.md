# Test Data Fixtures

1. Identify which interactions should be mocked, simulated or covered by real integration tests.
2. Build deterministic fixtures for valid, invalid, boundary and failure states.
3. Avoid production secrets or real personal information; synthesize representative records.
4. Isolate clock, network, filesystem and process state to prevent flaky tests.
5. Review fixture upkeep cost and ensure tests fail when contracts change.
